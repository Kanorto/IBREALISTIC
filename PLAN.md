# План реалистичного ралли — IBREALISTIC

> **Структура документа:** Завершённые фазы (1–5a) → Известные баги → Будущие фазы (6–16) с порядком зависимостей.
> Каждый шаг включает работу с переводами (lang/*.yml + triton.yml + triton/timingsystem.json).
> Функционал всегда реализуется **до** визуала: нельзя делать GUI без готового бэкенда.

## Порядок зависимостей между фазами

```
ФАЗА 6  (Баги и стабильность)      ← делать ПЕРВОЙ, без неё всё ненадёжно
   ↓
ФАЗА 7  (Версионирование серверов) ← нужно для совместимости клиент-сервер
   ↓

   ↓

   ↓

   ↓
ФАЗА 11 (Настройка треков: погода, время суток) ← зависит от соло-рейсов (нужны треки)
   ↓
ФАЗА 12 (Раллийные процедуры)     ← зависит от настроек треков
   ↓
ФАЗА 13 (Система поломок и износа) ← зависит от кастомизации + раллийных процедур
   ↓

   ↓
ФАЗА 15 (Поддержка рулей и педалей)← независимо, но после стабилизации физики
   ↓
```

# ИЗВЕСТНЫЕ БАГИ И ПРОБЛЕМЫ 🐛

## BUG-1: Накопление воздушного состояния ⚠️
**Приоритет:** ВЫСОКИЙ — влияет на геймплей
**Симптомы:**
- Первый прыжок проходит нормально (кроме резкой остановки при приземлении)
- Второй и последующие прыжки тянут машину в сторону
- Эффект накапливается: каждый следующий прыжок хуже предыдущего

**Вероятные причины:**
1. `vy` (боковая скорость) не полностью сбрасывается при приземлении — остаточная `vy` из воздуха переносится в наземную физику
2. `fyActual[]` (актуальные боковые силы колёс) сохраняют воздушные значения при переходе воздух→земля
3. `yawRate` накапливается в воздухе из-за остаточного демпфирования (AIR_YAW_RATE_DAMPING)
4. Коллизия при приземлении создаёт ложную боковую скорость через `expectedWorldVx/Vz` механизм
5. `prevVerticalVelocity` может некорректно обновляться между тиками

**Где искать:** `FourWheelPhysicsEngine.java`, строки 270–335 (airborne state, landing detection)

**Решение (план):**
- [ ] Добавить полный сброс `vy = 0`, `fyActual[i] = 0`, `yawRate = 0` при приземлении после длительного полёта
- [ ] Проверить `expectedWorldVx/Vz` — не создаёт ли коллизия при приземлении ложные значения
- [ ] Добавить логирование воздушного состояния для отладки (debug mode)
- [ ] Тестировать на треках с множественными прыжками

## BUG-2: Резкая остановка при приземлении ⚠️
**Приоритет:** СРЕДНИЙ
**Симптомы:** Машина теряет почти всю скорость при приземлении с прыжка
**Вероятная причина:** Vanilla `move()` + `updateVelocity()` клиппит скорость при столкновении с землёй
**Решение:** Сохранять `vx` перед `move()` и восстанавливать после, если разница слишком большая

  - [ ] При выходе с трека: сброс на серверную погоду

### Порядок реализации в каждой фазе
```
1. Бэкенд (данные, БД, менеджеры)
2. Пакеты (клиент-сервер, если нужно)
3. Команды (для тестирования без GUI)
4. Переводы (все языковые файлы)

6. GUI (ТОЛЬКО после работающего бэкенда)
7. Визуальные эффекты (ПОСЛЕДНИМИ)
```

### Переводы — в каждом шаге
Каждый шаг каждой фазы ДОЛЖЕН включать:
1. Добавление ключей в `lang/en_us.yml` (основной)
2. Добавление обёрток в `lang/triton.yml` (`[lang]ts.key[/lang]`)
3. Placeholder-переводы в остальных языковых файлах (`de_de.yml`, `id_id.yml`, `zh_cn.yml`, `pl_pl.yml`, `nl_nl.yml`, `es_es.yml`, `pt_br.yml`, `fr_fr.yml`)
4. Добавление записей в `triton/timingsystem.json` (en_GB, ru_RU, de_DE, pl_PL, nl_NL, es_ES, pt_BR, fr_FR)

- **MAJOR** (X.0.0): несовместимые изменения протокола
