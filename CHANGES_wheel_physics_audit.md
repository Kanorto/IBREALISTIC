# Изменения: Аудит системы 4 колёс и физики

## Дата
2026-02-11

## Краткое описание
Полный аудит и исправление системы отображения 4 колёс и физического движка. Исправлены критические проблемы с двойным применением ванильной физики поверх реалистичного движка и зависимость вращения колёс от FPS.

## Изменённые файлы

### Мод (OBURealistic)
- `src/main/java/dev/o7moon/openboatutils/mixin/BoatMixin.java` — подавление ванильной физики при активной реалистичной модели
- `src/main/java/dev/o7moon/openboatutils/client/WheelRenderer.java` — фреймрейт-независимое вращение колёс
- `src/main/java/dev/o7moon/openboatutils/mixin/BoatEntityRendererMixin.java` — передача tickDelta в рендер колёс

## Детальное описание изменений

### 1. Подавление ванильного ускорения при реалистичной физике
**Файл:** `BoatMixin.java`
**Строки:** forwardsAccel, turnAccel, backwardsAccel методы
**Что сделано:**
- Добавлена проверка `fourWheelPhysics.isEnabled()` — при активной реалистичной физике ванильные ускорения возвращают 0f
- Без этого исправления ванильное ускорение 0.04f (вперёд) и 0.005f (назад/поворот) стэкалось поверх физического движка

**Причина:**
Физический движок FourWheelPhysicsEngine полностью управляет ускорением через engineForce, brakingForce и аэродинамическое сопротивление. Ванильное ускорение создавало непреднамеренный дополнительный буст.

### 2. Подавление ванильного вращения (yaw) при реалистичной физике
**Файл:** `BoatMixin.java`
**Строки:** redirectYawVelocityIncrement метод
**Что сделано:**
- При активной реалистичной физике yawVelocity устанавливается в 0 вместо накопления ванильных значений
- Это предотвращает двойное вращение (от физического движка + ванильное)

**Причина:**
FourWheelPhysicsEngine рассчитывает yawRate на основе шинных сил и моментов. Ванильный yawVelocity (поворот на 1° за нажатие клавиши) конфликтовал с этим расчётом.

### 3. Подавление ванильного затухания скорости (velocity decay) на суше
**Файл:** `BoatMixin.java`
**Строки:** новый метод velocityDecayOnLand
**Что сделано:**
- Добавлен redirect на velocityDecay PUTFIELD ordinal=0 (ON_LAND)
- При активной реалистичной физике velocityDecay = 1.0f (нет затухания)
- Без реалистичной физики — ванильное поведение

**Причина:**
Ванильный velocityDecay (0.98 = nearbySlipperiness) множился на скорость ПОСЛЕ того, как физический движок уже рассчитал свою скорость с учётом сопротивления качению и аэродинамики. Это создавало дополнительное замедление ~2% за тик, делая машину заметно «вялой».

### 4. Фреймрейт-независимое вращение колёс
**Файл:** `WheelRenderer.java`
**Что сделано:**
- Разделена логика на tick-фазу (`tickWheelSpin()`) и render-фазу (`renderWheels()`)
- `tickWheelSpin()` вызывается из BoatMixin один раз за игровой тик
- `renderWheels()` интерполирует угол вращения с помощью tickDelta
- Добавлен параметр tickDelta в метод renderWheels()

**Причина:**
Ранее wheelSpinAngle обновлялся в render(), который вызывается с частотой FPS. На 60 FPS колёса крутились ~3x быстрее чем при 20 FPS, потому что умножение использовало фиксированный 0.05f (время тика).

### 5. Передача tickDelta в рендер колёс
**Файл:** `BoatEntityRendererMixin.java`
**Что сделано:**
- Для MC ≤1.21: tickDelta берётся из параметра render метода
- Для MC ≥1.21.3: tickDelta берётся из `MinecraftClient.getInstance().getRenderTickCounter().getTickDelta(true)`
- Передаётся в WheelRenderer.renderWheels() для плавной интерполяции

**Причина:**
Необходимо для корректной работы фреймрейт-независимого вращения колёс.
