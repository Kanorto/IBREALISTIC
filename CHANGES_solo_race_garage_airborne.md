# Изменения: Автоспавн лодки при соло забеге, гараж, физика полёта

## Дата
2026-02-18

## Краткое описание
Исправлены три проблемы: автоматический спавн лодки при начале соло забега,
некорректный парсинг пресетов гаража из конфигурации (UNKNOWN поля), и
нереалистичная физика полёта (крен и медленное падение).

## Изменённые файлы

### Мод (IBRealistic)
- `IBRealistic/src/main/java/dev/kanorto/ibrealistic/mixin/BoatMixin.java` — сброс визуального крена и наклона при полёте без air control
- `IBRealistic/src/main/java/dev/kanorto/ibrealistic/physics/FourWheelPhysicsEngine.java` — реалистичная гравитация при полёте, увеличенная терминальная скорость

### Плагин (TimingSystem)
- `TimingSystem/src/main/java/me/makkuusen/timing/system/race/SoloRaceManager.java` — автоспавн лодки при начале соло забега
- `TimingSystem/src/main/java/me/makkuusen/timing/system/economy/GarageManager.java` — поддержка inline YAML формата для пресетов
- `TimingSystem/src/main/resources/config.yml` — расширенный формат YAML для пресетов гаража

## Детальное описание изменений

### 1. Автоматический спавн лодки при соло забеге
**Файл:** `SoloRaceManager.java`
**Метод:** `startSoloRace()`
**Что сделано:**
- Удаление существующей лодки игрока перед началом забега
- Телепорт игрока на стартовую позицию через TaskChain (асинхронно)
- Применение конфигурации автомобиля (режим трека) перед спавном лодки
- Спавн новой лодки и автоматическая посадка игрока
- Запуск обратного отсчёта только после завершения всех подготовительных шагов

**Причина:**
Ранее `startSoloRace()` только телепортировал игрока, но не спавнил лодку и не
сажал его. Игрок должен был вручную сесть в лодку. Теперь процесс работает
автоматически, как при ресете — лодка спавнится в правильном режиме.

### 2. Гараж — парсинг пресетов из конфигурации
**Файл:** `GarageManager.java`
**Что сделано:**
- Добавлены хелпер-методы `getPresetString()` и `getPresetInt()` для чтения
  из ConfigurationSection ИЛИ Map (inline YAML формат)
- Все методы чтения пресетов (`getPresetName`, `getPresetPrice`, `getPresetLevel`,
  `resolvePresetId`, `getNamesForComponent`, `getPricesForComponent`,
  `getLevelsForComponent`) обновлены для использования новых хелперов
- Метод `ensureConfigDefaults()` обновлён для детекции и перезаписи inline
  Map-формата в правильный ConfigurationSection-формат
- Добавлен fallback на hardcoded DEFAULT_NAMES/PRICES/LEVELS при пустых ключах

**Файл:** `config.yml`
**Что сделано:**
- Преобразован inline YAML формат (`0: { name: "X", price: 0, level: 0 }`)
  в расширенный формат с отдельными строками для каждого поля

**Причина:**
Bukkit YamlConfiguration может парсить inline `{}` формат как Map объекты
вместо ConfigurationSection. `getConfigurationSection()` возвращает null для таких
Map, что приводит к отображению "UNKNOWN" для всех пресетов.

### 3. Физика полёта — крен и гравитация
**Файл:** `BoatMixin.java`
**Строки:** 115-120
**Что сделано:**
- При полёте без air control сбрасываются `visualRollAngle` и pitch (setPitch(0f))
- Предотвращает сохранение крена от последнего такта на земле

**Файл:** `FourWheelPhysicsEngine.java`
**Что сделано:**
- Увеличена терминальная скорость: `TERMINAL_FALL_VELOCITY` с -0.35 на -3.5 blocks/tick
  (~70 m/s, реалистично для автомобиля)
- Удалён искусственный `VERTICAL_DRAG_FACTOR`, который замедлял падение
- Теперь ванильная гравитация работает полноценно: не ограничивается
  искусственным драгом и низкой терминальной скоростью

**Причина:**
- Крен: при отсутствии air control, физика не выполнялась в воздухе,
  но визуальный крен от последнего наземного тика сохранялся
- Гравитация: старая модель ограничивала падение до 0.35 blocks/tick (7 m/s)
  и применяла драг 0.85x каждый тик, что замедляло падение нереалистично.
  Ванильная гравитация MC (~0.04 blocks/tick²) достаточна для реалистичного
  ускорения, но блокировалась искусственными ограничениями.
