# Изменения: Исправление регрессии скорости после версии 1.0.9

## Дата
2026-02-22

## Краткое описание
Исправлена регрессия скорости, введённая в PR #70 — автомобиль не набирал скорость выше 15-20 км/ч из-за того, что ванильный `velocityDecay` (применяемый Minecraft после вывода физического движка) уменьшал скорость сущности ниже ожидаемой, заставляя движок стартовать каждый тик с уменьшенной скорости.

- `src/main/java/dev/kanorto/ibrealistic/physics/FourWheelPhysicsEngine.java` — переработан блок VANILLA VELOCITY ISOLATION и COLLISION-AWARE VELOCITY INITIALIZATION

## Детальное описание изменений

### 1. Переработка блока Vanilla Velocity Isolation
**Файл:** `FourWheelPhysicsEngine.java`
**Строки:** 242-304

**Корневая причина проблемы:**
PR #70 расширил изоляцию скорости (velocity isolation) с «только в воздухе» на «всегда» (включая на земле). Логика была:
- Если скорость сущности > ожидаемой → использовать ожидаемую (фильтрует ванильные paddles)
- Если скорость сущности < ожидаемой → использовать скорость сущности (для детекции стен)

Проблема: ванильный `velocityDecay` (применяемый в `BoatEntity.tick()` ПОСЛЕ нашего mixin) уменьшает скорость сущности каждый тик. Даже с нашими хуками (ordinal 4 и 5 → decay=1.0), сущность может терять скорость из-за:
- `Entity.move()` клиппинг при ступеньках на блоках
- Ванильный `velocityDecay` для нехуканных состояний (IN_WATER)
- Мелкие потери при коллизионном разрешении

Когда скорость сущности < ожидаемой, движок принимал уменьшенную скорость сущности как стартовую точку. При `velocityDecay ≈ 0.95` равновесие наступало при ~16 км/ч — точно то, что описал пользователь.

**Что сделано:**
1. **Velocity Isolation теперь ВСЕГДА использует ожидаемую скорость** (если она доступна), а не только когда скорость сущности выше. Это делает физический движок полностью изолированным от ванильных модификаций скорости.

2. **Оригинальная скорость сущности сохраняется отдельно** (`entityWorldVx/Vz`) и используется ТОЛЬКО для детекции столкновений со стенами/блоками.

3. **Детекция коллизий сравнивает скорость сущности (до изоляции) с ожидаемой.** При обнаружении коллизии — используется скорость сущности для корректной обработки (стена действительно уменьшила скорость).

4. **Добавлена защита от ложных срабатываний коллизии** от ванильных paddles: условие `speedLoss > 0f &&` предотвращает детекцию коллизии, когда сущность БЫСТРЕЕ ожидаемого (paddles добавили скорость).

### Поток данных (до и после)

**До (PR #70, сломано):**
```
Тик N: Движок → vx=10 → setVelocity(0.5 b/t)
Ванилла: +paddles → 0.54 b/t → move() → 0.48 b/t → ×decay(0.95) → 0.456 b/t
Тик N+1: entity=0.456 → world=9.12 m/s < expected=10.0 → ИСПОЛЬЗУЕМ СУЩНОСТЬ
→ vx стартует с 9.12 вместо 10.0 → скорость ограничена!
```

**После (исправлено):**
```
Тик N: Движок → vx=10 → setVelocity(0.5 b/t)
Ванилла: +paddles → 0.54 b/t → move() → 0.48 b/t → ×decay(0.95) → 0.456 b/t
Тик N+1: expected=10.0 > threshold → ВСЕГДА ИСПОЛЬЗУЕМ ОЖИДАЕМУЮ
entity(0.456)→9.12 m/s сохранена для детекции коллизий
→ vx стартует с 10.0 (правильно!) → скорость развивается корректно!
```
