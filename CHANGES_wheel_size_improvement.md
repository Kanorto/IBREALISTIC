## Детальное описание изменений

### 1. Увеличение размеров колёс
**Файл:** `src/main/java/dev/o7moon/openboatutils/client/WheelRenderer.java`  
**Строки:** 25-30 (константы позиционирования)

**Изменённые константы:**
| Константа | Было | Стало | Описание |
|-----------|------|-------|----------|
| `WHEEL_RADIUS` | 0.25f | 0.4f | Визуальный радиус колеса в блоках |
| `WHEEL_Y_OFFSET` | 0.3f | 0.35f | Вертикальная позиция под центром лодки |
| `FRONT_Z_OFFSET` | 0.55f | 0.6f | Передняя ось (вперёд от центра) |
| `REAR_Z_OFFSET` | -0.55f | -0.6f | Задняя ось (назад от центра) |
| `LATERAL_OFFSET` | 0.55f | 0.7f | Половина ширины колеи (выступает за лодку) |

**Удалённые константы:**
| Константа | Было | Причина удаления |
|-----------|------|------------------|
| `WHEEL_WIDTH` | 0.15f | Не использовалась в коде, ширина контролируется через TIRE_HALF_WIDTH |

**Причина:**
Прежние колёса были слишком маленькими ("микроколёсики") и выглядели непропорционально для раллийной машины. Радиус увеличен на 60%.

### 2. Новая составная модель колеса
**Файл:** `src/main/java/dev/o7moon/openboatutils/client/WheelRenderer.java`  
**Строки:** 32-40 (константы модели), 63-95 (создание модели)

**Новые константы модели:**
| Константа | Значение | Блок-размер | Описание |
|-----------|----------|-------------|----------|
| `TIRE_HALF_WIDTH` | 1.5f | ~0.12 блоков (half) | Половина толщины шины вдоль оси |
| `TIRE_HALF_SIZE` | 5f | 0.4 блоков (half) | Половина высоты/глубины шины (= радиус) |
| `HUB_HALF_WIDTH` | 1.8f | ~0.14 блоков (half) | Половина толщины обода (чуть шире шины) |
| `HUB_HALF_SIZE` | 2.8f | ~0.22 блоков (half) | Половина размера обода (~56% от шины) |

**Формула масштабирования:**
```
scale = WHEEL_RADIUS / TIRE_HALF_SIZE = 0.4 / 5.0 = 0.08
block_size = model_units × scale
```

**Структура модели (было → стало):**

**БЫЛО:** 1 часть
- `wheel` — единственный кубоид 4×6×6 model units

**СТАЛО:** 3 части
- `tire_0` — основной кубоид шины (3×10×10 model units, масштаб 0.08)
  - Ориентация: 0° (базовая, `ModelTransform.NONE`)
  - Создаёт вертикальный/горизонтальный контур
- `tire_45` — дополнительный кубоид шины (3×10×10 model units, масштаб 0.08)
  - Ориентация: 45° вокруг оси X (`ModelTransform.rotation(π/4, 0, 0)`)
  - Перекрываясь с `tire_0`, создаёт октагональный профиль
- `hub` — центральный диск обода (3.6×5.6×5.6 model units, масштаб 0.08)
  - Ориентация: 0° (базовая)
  - Визуально отличается цветом от шины

**Текстуры (было → стало):**

**БЫЛО:** 1 текстура
- Все части: `minecraft:textures/block/black_concrete.png`

**СТАЛО:** 2 текстуры
- Шина (`tire_0`, `tire_45`): `minecraft:textures/block/black_concrete.png`
  - Цвет: 0x1F1F1F (≥1.21) / RGB 0.12f (≤1.20.4) — очень тёмный
- Обод (`hub`): `minecraft:textures/block/gray_concrete.png`
  - Цвет: 0x595959 (≥1.21) / RGB 0.35f (≤1.20.4) — серый

**Причина:**
Два перекрывающихся кубоида создают приближение к октагональной (8-угольной) форме вместо простого квадрата. Центральный диск обода другого цвета добавляет визуальную глубину и реализм.

### 3. Обновлённый метод рендеринга
**Файл:** `src/main/java/dev/o7moon/openboatutils/client/WheelRenderer.java`  
**Строки:** 119-154 (renderWheels), 160-206 (renderSingleWheel)

**Сигнатура renderSingleWheel (было → стало):**

```java
// БЫЛО:
private static void renderSingleWheel(MatrixStack matrices, ModelPart wheel,
                                       VertexConsumer vertexConsumer, int light, ...)

// СТАЛО:
private static void renderSingleWheel(MatrixStack matrices, ModelPart wheel,
                                       VertexConsumer tireConsumer, VertexConsumer hubConsumer,
                                       int light, ...)
```

**Изменения:**
- Вместо одного `VertexConsumer` — два: `tireConsumer` (для шины) и `hubConsumer` (для обода)
- Каждый использует свой `RenderLayer.getEntitySolid()` с разными текстурами
- Рендерятся 3 child-части вместо 1: `tire_0`, `tire_45`, `hub`

### 4. Визуальный подъём лодки
**Файл:** `src/main/java/dev/o7moon/openboatutils/mixin/BoatEntityRendererMixin.java`  
**Строки:** 24-27 (константа), 39-41 (≤1.21), 86-88 (≥1.21.3)

**Новая константа:**
```java
private static final float VISUAL_LIFT = 0.25f; // подъём лодки в блоках
```

**Реализация по версиям MC:**

| Версия MC | Точка инъекции | Координатная система | Код translate |
|-----------|----------------|---------------------|---------------|
| ≤1.21 | `interpolateBubbleWobble` (AFTER `scale(-1,-1,1)`) | Y инвертирована (+ = вниз) | `translate(0, -VISUAL_LIFT, 0)` |
| ≥1.21.3 | `scale(FFF)` (BEFORE `scale(-1,-1,1)`) | Y стандартная (+ = вверх) | `translate(0, +VISUAL_LIFT, 0)` |

**ВАЖНО: Различие направления Y!**
- В версии ≤1.21 инъекция происходит ПОСЛЕ `scale(-1,-1,1)`, поэтому Y ось инвертирована
- В версии ≥1.21.3 инъекция происходит ПЕРЕД `scale(-1,-1,1)`, поэтому Y ось стандартная
- Направление translate подобрано так, чтобы визуальный эффект был одинаковым: лодка поднимается ВВЕРХ

**Что НЕ изменяется:**
- Хитбокс лодки остаётся на месте (только визуальное смещение)
- Подъём применяется ТОЛЬКО когда realistic physics активна (проверка `isPlayerBoat` / `isEnabled`)
- Колёса поднимаются вместе с лодкой (одна матричная трансформация для всего)

**Причина:**
Пользователь хотел чтобы лодка визуально стояла "на колёсах", выше чем обычно, при этом не меняя физику.

---

### 5. Исправленный баг (выявлен при ревью)
**Файл:** `BoatEntityRendererMixin.java`
**Проблема:** Первоначально translate для ≥1.21.3 был `translate(0, -VISUAL_LIFT, 0)`, что двигало лодку ВНИЗ (так как Y ось ещё не инвертирована на этом этапе рендера)
**Решение:** Изменено на `translate(0, +VISUAL_LIFT, 0)` для ≥1.21.3

| Проблема | Решение |
|----------|---------|
| Прежние колёса слишком маленькие | Радиус увеличен с 0.25 до 0.4 (+60%) |
