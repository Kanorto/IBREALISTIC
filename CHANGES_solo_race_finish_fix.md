# Изменения: Исправление бага соло гонки и синхронизация обратного отсчёта

Исправлен критический баг, при котором соло гонка завершалась мгновенно при старте (игрок спавнился в зоне финиша). Обратный отсчёт переведён на таймстампы вместо серверных тиков для точной синхронизации клиент-сервер.

## Детальное описание изменений

### 1. Исправление мгновенного финиша при старте гонки
**Файл:** `TSListener.java` (метод `handleSoloRaceRegions`)
**Файл:** `RaceSession.java` (новое поле `hasLeftFinishRegion`)

**Проблема:**
Когда трек не имеет отдельного региона END, используется регион START как финишная линия.
Игрок спавнится на позиции GRID, которая находится внутри (или рядом с) регионом START.
После завершения обратного отсчёта состояние переходит в RACING, и на первом же тике
проверки регионов обнаруживается, что игрок находится в финишном регионе → гонка завершается мгновенно.

**Решение:**
Добавлен флаг `hasLeftFinishRegion` в `RaceSession`:
- Изначально `false`
- Устанавливается в `true` когда игрок **покидает** финишный регион
- Финиш разрешён только если `hasLeftFinishRegion == true`

Это корректно работает для обоих типов треков:
- **Кольцевые трассы** (START = финиш): игрок должен уехать из START и вернуться
- **Трассы с отдельным END**: игрок никогда не спавнится в END, поэтому `hasLeftFinishRegion` устанавливается в `true` на первом же тике

### 2. Обратный отсчёт по таймстампу
**Файл:** `SoloRaceManager.java` (метод `startCountdown`)
**Файл:** `RaceSession.java` (новое поле `goTimeMs`)

**Проблема:**
Обратный отсчёт использовал серверные тики (TaskChain с `delay(20)` × N итераций).
Серверные тики не всегда точно 50мс (зависит от TPS), поэтому переход COUNTDOWN→RACING
мог не совпадать с моментом "GO" на клиенте (который считает по `System.currentTimeMillis()`).
Также серверные сообщения обратного отсчёта могли приходить с задержкой, создавая рассинхронизацию
с клиентским визуальным обратным отсчётом (блоки, звуки, частицы).

**Решение:**
- `goTimeMs` сохраняется в `RaceSession` (абсолютное время в мс)
- Серверная логика использует `scheduleSyncRepeatingTask` каждые 500мс и проверяет `System.currentTimeMillis() >= goTimeMs`
- Когда таймстамп наступает → переход в RACING
- Серверные чат-сообщения обратного отсчёта удалены — весь визуал проводится на клиенте через `RaceCountdownRenderer`:
  - 5-4: красный блок + частицы пламени + звук HAT
  - 3-2-1: жёлтый блок + частицы END_ROD + звук HAT
  - GO: зелёный блок + частицы HAPPY_VILLAGER + звук PLING
- Клиент и сервер используют один и тот же `goTimeMs` → идеальная синхронизация
