# Изменения: Исправление управления и скорости в реалистичных режимах

## Дата
2026-02-11

## Краткое описание
Исправлены две критические проблемы в реалистичных режимах (REALISTIC_*), появившиеся после версии 1.0.1: инвертированное управление (лево/право перепутаны) и крайне медленная скорость движения (как ванильная лодка вместо реалистичной).

## Изменённые файлы

### Мод (OpenBoatUtilsRealistic)
- `src/main/java/dev/o7moon/openboatutils/mixin/BoatMixin.java` — инвертированы знаки управления, добавлена отмена vanilla updateVelocity

## Детальное описание изменений

### 1. Исправлено инвертированное управление
**Файл:** `BoatMixin.java`  
**Строки:** 147-148  
**Что сделано:**
- Инвертированы знаки steeringInput:
  - `if (minecraft.options.leftKey.isPressed()) steeringInput -= 1f;` (было +1f)
  - `if (minecraft.options.rightKey.isPressed()) steeringInput += 1f;` (было -1f)

**Причина:**
После одного из недавних обновлений (предположительно 1.0.2-1.0.3) управление стало инвертированным:
- A (left key) поворачивало НАПРАВО вместо НАЛЕВО
- D (right key) поворачивало НАЛЕВО вместо НАПРАВО

**Результат:**
Теперь управление правильное:
- A (left key) → поворот НАЛЕВО ✓
- D (right key) → поворот НАПРАВО ✓

### 2. Исправлена крайне медленная скорость
**Файл:** `BoatMixin.java`  
**Что сделано:**
- Добавлен новый метод `cancelUpdateVelocityForRealisticPhysics` с аннотацией @Inject(method = "updateVelocity", at = @At("HEAD"), cancellable = true)
- Метод полностью отменяет выполнение vanilla updateVelocity(), когда `OpenBoatUtils.fourWheelPhysics.isEnabled() == true`
- Реализовано для всех версий MC (1.20.4, 1.21, 1.21.3) через Stonecutter conditions

**Причина проблемы:**
После PR #15 (версия 1.0.2) были добавлены подавления vanilla physics для предотвращения двойного применения сил. Однако vanilla метод `updateVelocity()` всё ещё вызывался ПОСЛЕ того, как реалистичная физика устанавливала velocity. 

Порядок выполнения был:
1. `tick()` → `checkLocation()` (перехвачен) → реалистичная физика устанавливает velocity
2. `tick()` → `updatePaddles()` (подавлено для realistic physics)
3. `tick()` → **`updateVelocity()` ПЕРЕЗАПИСЫВАЛ velocity!** ← проблема

Хотя были добавлены редиректы для `velocityDecay` (устанавливается 1.0f вместо 0.98f), сам метод `updateVelocity()` всё равно выполнялся и мог изменять velocity другими способами, что приводило к медленной скорости "как ванильная лодка".

**Результат:**
Теперь vanilla `updateVelocity()` полностью пропускается при активной реалистичной физике. Velocity, установленная реалистичным движком (FourWheelPhysicsEngine), больше не перезаписывается. Машина движется с правильной реалистичной скоростью.

## Связь с предыдущими изменениями

### PR #15 (версия 1.0.2): "Fix vanilla physics interference"
В этом PR были добавлены подавления vanilla physics:
- Подавление vanilla acceleration (return 0f в forwardsAccel)
- Обнуление yawVelocity в updatePaddles
- Установка velocityDecay = 1.0f в updateVelocity

Однако этого было **недостаточно**, потому что сам метод `updateVelocity()` всё ещё выполнялся. Текущее исправление **завершает** работу PR #15, полностью отменяя `updateVelocity()`.

### Почему проблема не была замечена сразу?
Подавление vanilla physics в PR #15 работало частично:
- Acceleration подавлялся правильно
- YawVelocity подавлялся правильно  
- Но `updateVelocity()` всё ещё вносил изменения в velocity

Это создавало ситуацию, где машина двигалась медленно (как ванильная лодка), но не останавливалась полностью.
